Path with Maximum Probability

01

Problem Overview

You are given an undirected weighted graph of n nodes (0-indexed), represented by an edge list where edges[i] = [a, b] is an undirected edge connecting the nodes a and b with a probability of success of traversing that edge succProb[i].

Given two nodes start and end, find the path with the maximum probability of success to go from start to end and return its success probability.

If there is no path from start to end, return 0. Your answer will be accepted if it differs from the correct answer by at most 1e-5.

Constraints:

  • 2 <= n <= 10^4
  • 0 <= edges.length <= 2 * 10^4
  • edges[i].length == 2
  • 0 <= a, b < n
  • a != b
  • 0 <= succProb.length == edges.length <= 2 * 10^4
  • 0 <= succProb[i] <= 1
  • There is at most one edge between every two nodes.
Key Constraint

Probabilities multiply along a path (they are not additive), and each individual probability is between 0 and 1 — so the "best" path is the one that maximizes the product, not minimizes it. This inverts the usual Dijkstra direction: use a max-heap instead of a min-heap.

Output: 0.25000
Explanation: There are two paths from start to end, one having a probability of success = 0.2 and the other has 0.5 * 0.5 = 0.25.

Example 3​

Output: 0.00000
Explanation: There is no path between 0 and 2.

Rule of Thumb

When a graph problem asks to maximize a product of edge weights along a path (probabilities, success rates), run Dijkstra with a max-heap and multiply weights instead of adding them.

04

Approach

Core Insight

This is Dijkstra's algorithm with two twists: the heap is a max-heap (we want the largest probability, not the smallest distance), and edge relaxation multiplies probabilities instead of adding distances. Because multiplying by a value in [0, 1] never increases the probability, popping the max-probability node first still guarantees that once a node is finalized, no later path can beat it — the same greedy correctness argument as standard Dijkstra applies.

Build an undirected adjacency list — each edge is added in both directions since the graph is undirected. Push (start, probability=1) onto a max-heap. Pop the highest-probability node; if it's end, return its probability immediately. Otherwise, if not visited, mark it visited and relax all neighbors by pushing (neighbor, probability * edgeProbability).

06

Step-by-Step Solution

Build the undirected adjacency list —

For each edge (u, v) with probability p, add Node(v, p) to adjList[u] and Node(u, p) to adjList[v].

Seed the max-heap —

Push Node(start, 1) — probability of being at the start node is trivially 1.

Pop the highest-probability node repeatedly —

While the heap is non-empty, pop via popMax(). If already visited, skip. If it equals end, return the probability immediately.

Relax neighbors by multiplication —

For each unvisited neighbor, push Node(neighbor, currentProbability * edgeProbability).

Handle unreachable end —

If the heap empties without ever popping end, return the default result = 0.

07

Code Implementation

Swift Notes

Heap from swift-collections is used here via popMax() for max-heap behavior — no negation trick needed. Node.probability is a Double, and Comparable conformance orders by that field so popMax() always returns the currently most-probable frontier node. Returning inside the while loop the moment end is popped is both correct and an important early-exit optimization.

import Collections

class Solution {
    struct Node: Comparable {
        let destination: Int
        let probability: Double

        init(_ destination: Int, _ probability: Double) {
            self.destination = destination
            self.probability = probability
        }

        static func < (_ lhs: Self, _ rhs: Self) -> Bool {
            lhs.probability < rhs.probability
        }
    }

    func maxProbability(_ n: Int, _ edges: [[Int]], _ succProb: [Double], _ start_node: Int, _ end_node: Int) -> Double {
       var adjList = [Int: [Node]]()

       for i in 0..<edges.count {
            let edge = edges[i]
            adjList[edge[0], default: []].append(Node(edge[1], succProb[i]))
            adjList[edge[1], default: []].append(Node(edge[0], succProb[i]))
       }

        var visited = Set<Int>()
        var heap = Heap<Node>()
        heap.insert(Node(start_node, 1))
        var result: Double = 0

        while !heap.isEmpty {
            guard let node = heap.popMax(), !visited.contains(node.destination) else {
                continue
            }

            if node.destination == end_node {
                result = max(result, node.probability)
                return result
            }

            visited.insert(node.destination)

            let neighbors = adjList[node.destination, default: []]
            for neighbor in neighbors {
                guard !visited.contains(neighbor.destination) else { continue }
                heap.insert(Node(neighbor.destination, node.probability * neighbor.probability))
            }
        }
       return result
    }
}
08

Complexity Analysis

Time Complexity — O(E log E)

Since the graph is undirected, each of the E edges contributes two adjacency-list entries. Each edge can trigger at most one heap insertion when its source is finalized, so the heap holds up to O(E) entries, giving O(E log E) total for all inserts and pops.

Space Complexity — O(V + E)

The adjacency list stores O(E) entries (twice per edge for the undirected graph), the heap holds up to O(E) entries, and visited holds up to V nodes.

When to prefer Dijkstra with direct multiplication

Since all probabilities are non-negative and in [0, 1], multiplying directly is both simpler and numerically safer than converting to a -log(p) sum — reach for the max-heap approach whenever weights are multiplicative and bounded in [0, 1].

09

Common Pitfalls

✕01
Adding probabilities instead of multiplying
Treating this like standard Dijkstra and summing edge weights produces a value with no probabilistic meaning — probabilities along a path compose by multiplication, not addition.
Fix: Relax edges with `currentProbability * edgeProbability`, never `+`.
✕02
Using a min-heap instead of a max-heap
Popping the smallest probability first would explore the least-promising paths, and the greedy 'once popped, finalized' argument breaks down — the algorithm needs to always expand the currently highest-probability node.
Fix: Use `popMax()` and ensure `Node`'s `<` operator compares `probability` in the natural ascending direction (required for the max-heap's internal ordering).
✕03
Forgetting the undirected edge insertion
Adding the edge only in one direction silently turns the graph directed, making some valid paths unreachable.
Fix: Insert both `adjList[u].append(Node(v, p))` and `adjList[v].append(Node(u, p))` for every edge.
