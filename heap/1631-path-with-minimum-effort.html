Path With Minimum Effort

#1631MediumDijkstra-Style Min-Heap — Minimize Path MaximumLeetCode ↗

Path With Minimum Effort

01

Problem Overview

You are a hiker preparing for an upcoming hike. You are given heights, a 2D array of size rows x columns, where heights[row][col] represents the height of cell (row, col). You are situated in the top-left cell, (0, 0), and you hope to travel to the bottom-right cell, (rows-1, columns-1) (i.e., 0-indexed). You can move up, down, left, or right, and you wish to find a route that requires the minimum effort.

A route's effort is the maximum absolute difference in heights between two consecutive cells of the route.

Return the minimum effort required to travel from the top-left cell to the bottom-right cell.

Constraints:

  • rows == heights.length
  • columns == heights[i].length
  • 1 <= rows, columns <= 100
  • 1 <= rows * columns <= 10^4
  • 0 <= heights[i][j] <= 10^6
Key Constraint

Effort is defined as the maximum absolute height difference along the route, not the sum of differences. This means the "cost" of extending a path is max(currentEffort, abs(heightDiff)), not addition — the same running-maximum pattern as minimizing a path's bottleneck value.

Rule of Thumb

Any grid problem that minimizes the largest single step-cost along a path (not the total cost) is a running-maximum Dijkstra variant — swap the usual + relaxation for max(...).

04

Approach

Core Insight

Run Dijkstra where the "distance" to a cell is the minimum possible value of the maximum height difference seen along any path to it. A min-heap always expands the frontier cell with the currently smallest bottleneck first, guaranteeing that popping the destination (rows-1, cols-1) yields the true minimum effort — the same greedy correctness argument as classic Dijkstra, just with max in place of +.

Push (0, 0, 0) onto a min-heap keyed by effort. Maintain a destinations grid tracking the best (lowest) effort found so far for each cell, initialized to Int.max except the start. Pop the smallest-effort cell; if it's the destination, return its value immediately. Otherwise, for each of the four neighbors, compute newDiff = max(currentDiff, abs(heights[neighbor] - heights[current])) and push it only if it improves the neighbor's recorded best.

06

Step-by-Step Solution

Initialize the heap and tracking grid —

Push Grid(0, 0, 0) onto the min-heap. Set destinations[0][0] = 0; all other cells start at Int.max.

Pop the lowest-effort cell —

While the heap is non-empty, pop the cell with the smallest tracked effort. If it is (rows-1, cols-1), return its value immediately.

Skip stale entries —

If the popped effort exceeds the best recorded value for that cell, a better path was already found — skip it.

Relax the four neighbors —

For each in-bounds neighbor, compute newDiff = max(currentDiff, abs(heights[neighbor] - heights[current])). Push it and update the tracking grid only if it improves the neighbor's recorded best.

07

Code Implementation

Swift Notes

Heap from swift-collections (import Collections) is used via popMin(). The Grid struct's Comparable conformance compares only diff, so the heap surfaces the cell with the smallest bottleneck effort next. Checking grid.diff > destinations[grid.r][grid.c] before expanding is the same lazy-deletion trick used to discard stale heap entries without a decrease-key operation.

import Collections

class Solution {
    struct Grid: Comparable {
        let diff: Int
        let r: Int
        let c: Int

        init(_ diff: Int, _ r: Int, _ c: Int) {
            self.diff = diff
            self.r = r
            self.c = c
        }

        static func < (_ lhs: Self, _ rhs: Self) -> Bool {
            return lhs.diff < rhs.diff
        }
    }

    func minimumEffortPath(_ heights: [[Int]]) -> Int {
        let dirs = [(0, 1), (1, 0), (-1, 0), (0, -1)]
        let rows = heights.count
        let cols = heights[0].count

        // Setup heap and destionation with max value
        var heap = Heap<Grid>() 
        var destinations = Array(repeating: Array(repeating: Int.max, count: cols), count: rows)

        // Starting condition, reset the destination for the first item
        heap.insert(Grid(0, 0, 0))
        destinations[0][0] = 0

        while !heap.isEmpty {
            guard let grid = heap.popMin() else {
                break
            } 

            // Early exit: when reach destination, we can return immediatedly and it is guaranted minimum
            if grid.r == rows - 1 && grid.c == cols - 1 {    
                return grid.diff      
            }

            // Optimisation: If the current is bigger, then we skip it
            if grid.diff > destinations[grid.r][grid.c] {
                continue
            }

            for dir in dirs {
                let newR = grid.r + dir.0
                let newC = grid.c + dir.1

                guard newR < rows,
                    newC < cols,
                    newR >= 0,
                    newC >= 0 else {
                        continue
                    }
                
                // Calculate new diff / effort from the current to next one
                let newDiff = max(grid.diff, abs(heights[newR][newC] - heights[grid.r][grid.c]))
                
                // Only insert the path if it is better than we have stored
                guard newDiff < destinations[newR][newC] else { continue }
                heap.insert(Grid(newDiff, newR, newC))

                // Update the maximum diffing for this position
                destinations[newR][newC] = newDiff
                
            }

        }

        return 0
    }
}

Complexity Analysis

Time Complexity — O(rows · cols · log(rows · cols))

There are rows * cols cells, each with up to 4 neighbors, so at most O(rows * cols) heap insertions occur, each costing O(log(rows * cols)).

Space Complexity — O(rows · cols)

The destinations tracking grid and the heap both hold up to O(rows * cols) entries in the worst case.

When to prefer the min-heap approach

The min-heap approach is a single clean pass with an early exit, avoiding the repeated connectivity checks of binary search — prefer it when you want one straightforward implementation rather than tuning a binary-search predicate.

09

Common Pitfalls

✕01
Summing height differences instead of tracking the maximum
Effort is defined as the single largest step, not the cumulative sum — adding differences instead of taking `max` produces a value with no meaning to the problem.
Fix: Compute `newDiff = max(currentDiff, abs(heights[newR][newC] - heights[r][c]))`, never `+`.
✕02
Not exiting early at the destination
Continuing to process the heap after popping `(rows-1, cols-1)` wastes time, since that pop is already guaranteed optimal by the min-heap ordering.
Fix: Return immediately when the popped cell equals `(rows - 1, cols - 1)`.
✕03
Missing the absolute value on height differences
Height can decrease as well as increase between adjacent cells; using a signed difference instead of `abs(...)` can produce a negative effort, which is never a valid answer.
Fix: Always wrap the height difference in `abs(...)` before taking the max.
